# AI Agent Guidelines for universal-login

This document provides context and guidelines for AI coding assistants working with the universal-login codebase.

## Your Role

You are a TypeScript SDK engineer working on universal-login, the monorepo behind the Auth0 ACUL JS and React browser SDKs, which render Auth0's Universal Login screens. The React package is code-generated from the JS core.

---

## Project Structure

An npm-workspaces monorepo publishing two packages in lockstep: `@auth0/auth0-acul-js` is the core browser SDK, and `@auth0/auth0-acul-react` is a React wrapper whose screen layer is **generated** from the core SDK's TypeDoc output.

```
.
├── package.json                        # Root: workspaces + aggregate scripts (lint/test/build run --workspaces)
├── scripts/                           # Repo tooling: Node-version guard, local-install guard, unified docs
├── packages/auth0-acul-js/            # @auth0/auth0-acul-js — core browser SDK (no runtime dependencies)
│   ├── src/
│   │   ├── screens/<screen-name>/     # One dir per ACUL screen: index.ts (screen class) + screen/transaction overrides
│   │   ├── models/                    # Context models; base-context.ts reads window.universal_login_context
│   │   ├── utils/                     # form-handler.ts (form POST + telemetry), errors.ts, validators, passkeys
│   │   ├── shared/, common/           # Cross-screen helpers and shared exports
│   │   ├── constants/                 # ScreenIds, FormActions, Errors
│   │   ├── index.ts                   # Public entry (screens + errors + common + interfaces)
│   │   └── export.ts                  # TypeDoc entry point
│   ├── interfaces/                    # Published type contract, mirrors src/ (screens/, models/, utils/, export/)
│   ├── tests/unit/                    # Jest (jsdom) unit tests, mirroring src/screens
│   ├── examples/                      # Hand-written per-screen usage snippets (*.md)
│   └── docs/                          # Generated TypeDoc output incl. index.json — do not hand-edit
├── packages/auth0-acul-react/         # @auth0/auth0-acul-react — React wrapper over the core SDK
│   ├── src/
│   │   ├── screens/<screen-name>.tsx  # GENERATED by `generate:sdk` — one hook module per screen
│   │   ├── hooks/                     # ContextHooks factory + common/ and utility/ hooks
│   │   ├── state/                     # instance-store.ts (screen singletons), error-store.ts
│   │   ├── telemetry.ts               # Sets globalThis.__ACUL_SDK_NAME__/__VERSION__ before core imports
│   │   └── index.ts                   # GENERATED public entry — re-exports every use<Screen> hook
│   ├── scripts/generate-sdk/          # Codegen: core SDK docs/index.json → src/screens/ + src/index.ts
│   ├── tests/                         # Jest + React Testing Library; tests/screens/ is generated
│   └── examples/                      # GENERATED per-screen React snippets (`generate:examples`)
└── .github/workflows/                 # CI (lint+test+build), Monorepo Release, Snyk, SCA, Claude PR review
```

## Boundaries

### ✅ Always Do

- Run `npm run lint --workspaces` and `npm test --workspaces` before committing — exactly what CI runs.
- Add or update Jest unit tests for new functionality: core-SDK tests in `packages/auth0-acul-js/tests/unit/` (mirroring `src/screens/`), React tests in `packages/auth0-acul-react/tests/`.
- Keep `packages/auth0-acul-js/interfaces/` in lockstep with `src/` — a new or changed screen method, option, or context field must update its interface in the same PR. `interfaces/` is the published type contract.
- **Regenerate the React screen layer rather than hand-writing it.** After changing a core-SDK screen's public methods or types: run `npm run docs` in `packages/auth0-acul-js` (refreshes `docs/index.json`), then `npm run generate:sdk` in `packages/auth0-acul-react`.
- Add a new core-SDK screen as `src/screens/<kebab-case>/index.ts` (class extending `BaseContext`, with a `static screenIdentifier`), and register it in the `src/screens/index.ts` barrel plus `ScreenIds` in `src/constants/enums.ts`.
- Throw the typed errors from `packages/auth0-acul-js/src/utils/errors.ts` — `ValidationError`, `ConfigurationError`, `Auth0Error`, all extending `AculError`. Never throw a bare `Error`.
- Keep each package's `.version` and its `package.json` `"version"` in sync — both are version sources, coupled by `.shiprc`.
- Update the affected package's `README.md` in the same PR when you change the public API, options, or a supported integration pattern; update `MIGRATION_JS_TO_REACT.md` when the JS↔React mapping changes. This repo has **no `EXAMPLES.md`** — per-screen snippets live under each package's `examples/`.
- When adding a **new form submission path to Auth0**, route it through `FormHandler` in `packages/auth0-acul-js/src/utils/form-handler.ts` so the submission carries the transaction `state` and the `acul-sdk` telemetry field — don't build a form or POST by hand.

### ⚠️ Ask First

- **Any breaking change — always ask first.** Never change or remove a public screen method, exported hook, interface field, or option default on your own initiative.
- Adding new dependencies or bumping existing ones — the core SDK deliberately ships with no runtime dependencies.
- Modifying public API signatures or anything under `packages/auth0-acul-js/interfaces/`.
- Changes to CI/CD configuration (`.github/workflows/`, `.github/actions/`).
- Changing the codegen under `packages/auth0-acul-react/scripts/` — those scripts rewrite the entire generated screen layer, its tests, and its examples.
- Modifying security-relevant code: `utils/passkeys.ts`, `utils/validate-password.ts`, `utils/validate-username.ts`, `models/untrusted-data.ts`, or the telemetry field in `utils/form-handler.ts`.
- Bumping the `@auth0/auth0-acul-js` version pinned in `packages/auth0-acul-react/package.json` — release tooling owns it.

### 🚫 Never Do

- Commit secrets, API keys, or tokens.
- Log or persist end-user credentials, passkey material, OTP codes, or raw `window.universal_login_context` contents.
- Hand-edit generated output: `packages/auth0-acul-react/src/screens/*.tsx`, `packages/auth0-acul-react/src/index.ts`, `packages/auth0-acul-react/tests/screens/`, `packages/auth0-acul-react/examples/`, either package's `docs/` (TypeDoc), `CHANGELOG.md`, `NOTICE`, `coverage/`, or lock files.
- Remove or skip failing tests without fixing the underlying cause.
- Modify `node_modules/` or `dist/`.
- Run `npm install` inside a package directory — a root `preinstall` guard (`scripts/block-local-install.js`) blocks it. Install from the repo root.
- Break backward compatibility without explicit approval (see Ask First).

## Security Considerations

These SDKs run **in the browser on Auth0's Universal Login pages** and handle end-user credentials. The following are detected from the code and are non-negotiable:

- **All screen input arrives untrusted.** State comes from `window.universal_login_context` (`src/models/base-context.ts`), and `src/models/untrusted-data.ts` explicitly models client-supplied `submittedFormData` and `authorizationParams`. Never interpolate context values into HTML, and never trust them for control flow without validating first.
- **Submission is a form POST, not `fetch`.** `src/utils/form-handler.ts` builds a hidden-input form carrying the transaction `state` and posts to the Auth0 endpoint. Never drop, forge, or reuse `state` — it binds the submission to the transaction.
- **Client-side validation is a UX aid, not the security boundary.** `utils/validate-password.ts` and `utils/validate-username.ts` mirror tenant policy for feedback only; never treat them as authoritative or use them to relax what the server enforces.
- **WebAuthn / passkeys.** Ceremonies live in `utils/passkeys.ts`. Never log, cache, or persist credential material or challenges.
- **Secrets.** Nothing credential-shaped belongs in this repo — the SDKs receive everything at runtime from the Universal Login context. Snyk and SCA scans run in CI (`.github/workflows/snyk.yml`, `sca_scan.yml`).
- **Telemetry** is an `acul-sdk` hidden form field (`<sdk-name>@<version>`) added by `FormHandler.addTelemetryField`. Wrapper SDKs override it via `globalThis.__ACUL_SDK_NAME__` / `__ACUL_SDK_VERSION__`, set in the React package's `src/telemetry.ts`. The detected mechanism has no opt-out toggle; don't add one unilaterally, and never put anything but SDK name and version in that field.

## Commands

```bash
npm run lint --workspaces    # ESLint, both packages
npm test --workspaces        # Jest unit tests + coverage, both packages
npm run build:local          # Rollup build of both packages
```

Those three are exactly what CI runs. Note that root `npm run build` is heavier — the core SDK's `build` chains clean → lint → test → docs → rollup.

See [references/commands.md](references/commands.md) for the full list (codegen, docs, watch mode, per-package builds). Read only when you need to run, build, or generate something beyond the three above.

## Testing

Jest with `ts-jest` in ESM mode and a `jsdom` environment, in both packages. `npm test --workspaces` is the safe default — unit-only, no credentials and no network. Coverage is collected on every run but **no threshold is enforced**.

See [references/testing.md](references/testing.md) for layout, conventions, mocking, and the generated React screen tests. Read when writing or running tests.

## Code Style

TypeScript throughout, ESM (`"type": "module"`), flat-config ESLint + Prettier per package. Single quotes everywhere; print width 100 in the React package, Prettier's default 80 in the core SDK. Files and directories are kebab-case, classes PascalCase, and a screen directory name matches its `ScreenIds` value. CI-enforced rules worth knowing before you write code: **explicit function return types**, **no `any`** (including `no-unsafe-assignment` / `no-unsafe-member-access`), **`import type` for type-only imports**, **alphabetized `import/order` with newlines between groups**, and **strict `eqeqeq`**.

See [references/code-style.md](references/code-style.md) for the per-package rule split, patterns, and good/bad examples. Read before writing non-trivial new code.

## Git Workflow

Branch off `master`, named after the Jira ticket (e.g. `SDK-10301`). Commits and PR titles follow Conventional Commits (`feat:`, `fix:`, `chore:`, `build(deps):`). Release branches are `release/*`; merging one into `master` triggers the Monorepo Release workflow.

See [references/git-workflow.md](references/git-workflow.md) for branch, commit, and PR conventions. Read when preparing a commit or PR.

## Common Pitfalls

Top traps: the React screen layer is generated, so hand edits get overwritten; `generate:sdk` reads the core SDK's `docs/index.json`, so stale TypeDoc output silently yields a stale React API; `npm install` must run from the repo root; Node 22 is enforced by a `preinstall` guard.

See [references/pitfalls.md](references/pitfalls.md) for the full list with fixes. Read when a command fails unexpectedly or generated output looks wrong.

## Docs Update Rules

Treat docs as a first-class deliverable: a PR that changes the public API, an option, or an integration pattern is not complete until the affected package `README.md` (and `MIGRATION_JS_TO_REACT.md`, where the JS↔React mapping changes) is updated in the same PR.

See [references/docs-update.md](references/docs-update.md) for the tracked-docs inventory and the code-to-docs mapping. Read when changing public API, options, or examples.
